# 第一阶段架构审查与修复验收

## 范围与结论

本项目是单用户 macOS 原生桌面应用：读取与本人相关的未完成飞书任务，保留本地草稿，由用户确认后写入 TAPD。审查假设一个数据目录由单 actor 管理，不把它按多租户服务评估。

审查基线为 `e1e6de7`，范围是第一阶段相对 `main` 的完整代码，而非最后一个提交。基线约 5.7 万新增行包含锁文件及上游编辑器；对应用、自有桥接和核心实现作深入路径审查，对 vendored 编辑器聚焦本地补丁，不声称逐行审完全部上游代码。

三路独立审查分别覆盖核心持久化与写入安全、worker/账号生命周期、原生 UI 与编辑器；父线程补查进程、安装契约、刷新调度、依赖及打包，并验收子 agent 修复。实现子 agent 曾因供应商中断停止；保留版本经父线程拉入、检查和补测，不把子 agent 的完成状态当成通过证据。

**最终结论：A1–A8 已修复并通过父线程整合验收。独立复核发现的确认会话失效及断开库故障缺口也已补修；未发现仍需阻止第一阶段有限范围落地的已确认 P0/P1 问题。保留的恢复、容量与真实联调边界见下文。尚未合并主分支或执行远端发布。**

## 架构判断

- UI 实体负责输入和窗口生命周期；共享 Model 负责展示状态和事件路由。
- worker actor 串行拥有业务数据库、写入日志和配置状态；只读任务在后台执行，结果按账号及配置代数合并。
- 全局 preferences 是配置的唯一提交点；每个账号 Engine 的配置仅是运行时副本。业务快照和不确定写入日志仍必须先持久化再推进内存。
- CliGateway 负责具体协议；受控进程层负责环境白名单、取消、超时、输出限长和脱敏。
- Keychain 与 CLI 原生凭据存储不是 SQLite 配置事务的一部分。凭据已成功改变后，旧身份必须立即失效，不能因后续配置保存失败恢复旧授权。

这套分层适合当前个人应用。没有证据支持为本阶段增加服务端、通用事务框架或后台守护进程。主要问题来自跨层生命周期和回执语义，而不是模块数量不足。

## 已确认问题、修复方案与验收

### A1 · P1 · 正常退出可能早于 OAuth/CLI 后台操作结束

- **原触发：** 授权交换或版本探测在途时退出；actor 没有统一取消和等待后台线程，数据锁可能先于原生操作结束释放。旧授权被从 pending 移除后仍可能运行。
- **修复：** WorkerSender 显式 shutdown 关闭业务入口；独立跟踪全部后台线程，取消并 join 后释放锁、广播完成。GPUI quit hook 等待完成，并使用正常 C 进程退出屏障应对 Cocoa 不保证返回主循环的问题。进程级任务取消覆盖原生准备及版本探测。
- **证据：** 假 CLI 退出后延迟写标记的子进程测试；正常返回与 `process::exit`；重复 shutdown；退出前拒绝新写入；旧授权结束前锁不可重入。均已通过。
- **代码：** [worker shutdown](../../crates/desktop/src/worker.rs#L298)、[线程回收](../../crates/desktop/src/worker.rs#L600)、[退出屏障](../../crates/desktop/src/shutdown_exit.rs#L1)、[进程退出测试](../../crates/desktop/src/worker_connection_tests.rs#L1130)。
- **边界：** 强杀、abort、断电不保证执行屏障。已经进行的同步写入或安装可能需要等待其既有超时，不承诺立即退出；没有用真实 OAuth 验收。

### A2 · P2 · CLI 版本白名单只约束诊断，不约束业务

- **原触发：** CLI 版本不受支持，但仍返回可解析 JSON，导致检测失败而读取甚至写入继续执行。
- **修复：** 账号业务在加载凭据和执行命令前按同一版本策略检查两端；检查按操作执行，不在每条任务详情内重复。独立连接测试仍只检查选中服务。
- **证据：** 假 CLI 对未知版本仍可成功返回身份信息的正对照；Refresh、目录、Submit、Recover 均在业务命令之前被阻止；独立 TAPD 测试不要求 Lark 可用。均已通过。
- **代码：** [共同门禁](../../crates/desktop/src/worker.rs#L936)。
- **影响：** 当前支持 Lark 1.0.96、TAPD 1.8.1/1.15.0。用户原日志中“读取成功但检测失败”的实际原因仍需具体检测详情确认，不能仅据代码缺口推断其版本。

### A3 · P1 · 未保存编辑可被关闭、切换或重复点击静默丢弃

- **原触发：** 修改标题/正文/附件后重复点击当前任务、选择其他任务、关闭主窗口；表单实体被重建且无保护。已保存草稿并未发现丢失。
- **修复：** 同任务选择 no-op；以加载或成功保存的草稿为比较基线；切换、原生关闭、Cmd-W、应用 Quit action 和托盘退出前提供取消/明确丢弃。用户取消后使用既有保存草稿按钮，不增加隐式远端写入。
- **证据：** GPUI 输入、取消/丢弃分支、成功保存后 clean、保存回执不覆盖后续输入、pending 媒体保护等测试通过。
- **整合补修：** 独立复核发现旧确认可能越过账号/scope 失效，父线程新增失败测试并修复：失效时更新 session、清除旧基线，确认时核对账号，切换时重验目标范围和 busy 状态。
- **代码：** [Quit 路由](../../crates/desktop/src/ui.rs#L641)、[dirty/确认](../../crates/desktop/src/ui.rs#L1389)。
- **边界：** GPUI fake platform 的 quit 是空操作，UI 测试证明路由和确认，不冒充实际 Cocoa 退出验收；强杀不会恢复未保存输入。账号/范围安全失效仍会清理旧编辑会话。

### A4 · P2 · 前缀迟到快照会清空下一条输入

- **原触发：** 提交前缀 A 后继续输入 B，A 的快照或删除旧前缀的快照到达，无条件重置新增表单。
- **修复：** 列表快照只更新列表；对应保存成功、项目和输入仍匹配时才结束表单。用户输入变化、取消或删除操作清除旧提交标记，前缀字节仍原样保留。
- **证据：** 延迟消费 A 的回执、先输入 B，再处理保存及删除回执，断言 B 和打开状态保留。
- **代码：** [回归测试](../../crates/desktop/src/ui/prefix_settings_tests.rs#L212)。

### A5 · P2 · 安装失败后确认面板与后台状态不一致

- **原触发：** 确认被提前 take，安装失败后面板仍在，用户再次确认却被要求重新审阅计划。
- **修复：** 安装失败保留已审阅计划，只有成功后清空；重试仍必须由用户显式点击，不自动重装或覆盖现有版本。
- **证据：** 临时目录故障让安装在任何下载/命令执行前失败；两次显式确认均进入实际安装前置校验，没有丢失确认。
- **代码：** [确认校验](../../crates/desktop/src/worker.rs#L1401)。

### A6 · P2 · 配置双库部分提交导致失败反馈与重启结果矛盾

- **原触发：** 全局偏好保存成功，profile 库写入失败；内存和 UI 留旧值，重启却采用全局新值。
- **修复：** preferences 为唯一配置提交点；全局保存成功后同步 actor/profile 的运行时副本。profile 磁盘副本不再成为设置成功的第二个条件；启动及账号切换恢复权威配置。核心设置验证规则共用，业务持久化顺序不变。
- **证据：** 真实临时 SQLite 的 INSERT/UPDATE 故障触发器；主题与 CLI 路径的保存反馈、当前状态及重启一致性；全局提交失败不推进普通配置及在途代数。均已通过。
- **整合补修：** 凭据成功写入后再发生偏好故障与普通配置失败不同。父线程用排队的旧代完成消息先复现，再确保旧身份无条件失效、不能合并旧结果。独立复核还发现断开库打开失败时旧数据可能被贴上空身份：现已将断开库打开前移到任何凭据修改之前，失败则不改凭据或身份；成功后交换已准备好的 Engine。该故障也有先红后绿的回归测试，复核者随后只读检查父线程实际代码并确认关闭。
- **代码：** [配置提交](../../crates/desktop/src/worker.rs#L1057)、[运行时配置副本](../../crates/core/src/lib.rs#L566)、[断开库故障测试](../../crates/desktop/src/worker_settings_tests.rs#L255)、[凭据故障测试](../../crates/desktop/src/worker_settings_tests.rs#L310)。

### A7 · P2 · 节流测试使用了错误的时间采样位置

- **原触发：** Python 进程入口的启动延迟不一致，产生约 57.5ms 的观察间隔，不能说明 Rust 发放许可的 125ms 约束失效。
- **修复：** 在测试构建中记录锁内实际许可时刻，覆盖同一 pacer 的两批并发及批次边界；进程集成测试验证分页、完整性和顺序。未改变生产限速、并发、冷却或预算。
- **证据：** 审查首次出现一次失败，单项重跑通过；修复子 agent 重复相关测试 5 轮通过。父线程桥接全套 94 项通过。
- **代码：** [许可时间测试](../../crates/bridge/src/read_pacing.rs#L88)。

### A8 · P2 · 管道截止时间被误归类为普通 I/O 错误

- **验收发现：** 一轮完整测试中 `passes_stdin_and_env_without_shell_interpolation` 报 `CLI I/O failed`；该次原错误未保留底层 I/O 类型，不能回溯断言其确切原因，也不能用单项重跑通过抹掉失败。
- **确定性复现：** 子进程退出但脱离进程组的后代保留管道，管道达到截止时间时，原实现仍返回泛化 I/O 错误。新增类型断言先失败，确认了分类缺口。
- **修复：** stdin/stdout/stderr 的 TimedOut 保留为 `CallTimeout`，与进程超时共用规则，不输出原始异常内容。参数内容契约测试的专用预算从 2 秒调整为 5 秒，避免将其兼作负载计时测试；专门的 80ms/700ms 超时约束和生产预算没有放宽。
- **验收：** 修复后重新运行完整 workspace、严格 Clippy、编辑器测试与打包，全部通过。
- **代码：** [进程管道处理](../../crates/bridge/src/process.rs#L113)。

## 保留限制与下一阶段决策

1. **附件不确定后的人工恢复缺口（P2）：** 真实临时 SQLite 重启复现了 `record.uncertain=false`、附件 `uncertain=true` 时，提交预检阻止继续，而任务级 Recover 不适用。当前无人工认领回执入口，可能阻塞该任务后续正文提交。不能通过直接清标记或自动重传解决；下一阶段需选择“验证并认领远端附件”或“明确放弃跟踪且保留历史”。
2. **远端更新不是原子条件写：** 提交前比较之后，其他人仍可能在 TAPD 网页修改同一对象。当前文档已披露窗口，未核实服务端条件写能力；重复读取不能消除该窗口。
3. **容量上限不是 SLA：** 全轮 120 秒、至少 125ms 发起间隔、最多 1000 候选是安全限制；1000 条全部需详情时仅发起间隔就超过预算。当前真实日志的 30 条未完成任务已成功，但不承诺接近上限仍可完成。
4. **CLI 版本与原生运行验收：** 新门禁会阻止白名单外版本；必须在真实环境确认版本和检测详情。未扩展未经验证的版本兼容范围。
5. **已知依赖警告：** `block v0.1.6` 存在 Rust 未来兼容性警告；当前工具链通过，不代表未来工具链无风险。

以上不是“已修复”的项目。第一阶段可按任务读取/编辑、明确确认写入的实验性桌面工具定位验收，不宜宣称真实 TAPD 写入、上传和所有异常恢复均已完成生产验证。

## 建议落地顺序

1. 保留本报告和回归测试；代码审查、修复及父线程自动化验收已完成，不自动视为真实业务写入验收。
2. 用新版做一次人工冒烟：CLI 版本检查、未完成任务刷新、脏草稿切换/关闭取消、设置前缀连续输入、正常退出后重开。无需为这一检查执行真实 TAPD 写入。
3. 在 Delta Review Changes 中审查相对 main 的完整差异，不只看最后提交。
4. 用户确认后通过 Land Changes 合入原始本地仓库 main；当前仅有 local remote，不默认发布到外部仓库，不强推，不顺带清理分支或线程。
5. 下一阶段从更新后的 main 新建线程，优先设计附件人工恢复、真实 TAPD 写入验收，再讨论大任务量增量扫描。
