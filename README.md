# Lark → TAPD

仅面向 macOS 的飞书任务同步桌面应用。Rust + GPUI Kit，马尔斯绿主题，中英文、亮色/暗色/跟随系统，SQLite 持久化与设备 Keychain 凭证存储。

**飞书是来源，写入由你确认。** 后台检查不会自动覆盖 TAPD；编辑后直接点击「导入 TAPD / 更新到 TAPD」写入，不再经过预览页。默认启动真实模式；`LARK2TAPD_MOCK=1` 启动隔离的演示模式，不读取真实凭证或访问业务服务。模式在进程启动时确定，界面不再提供切换按钮。

## 本地运行

需要 macOS、Rust 2024 工具链、Xcode 与命令行开发工具。项目锁定 GPUI Kit 0.7.1，使用 Toasty 0.11；请提交并保留 `Cargo.lock`。

```sh
# 演示模式：不访问真实账户或安装工具
LARK2TAPD_MOCK=1 cargo run --locked -p lark2tapd
# 真实模式（默认，也可明确设为 0）
LARK2TAPD_MOCK=0 cargo run --locked -p lark2tapd
# 命令行开关高于环境变量；测试独立的数据目录
cargo run --locked -p lark2tapd -- --mock --data-dir ./target/demo-data
```

构建可双击启动的桌面应用：

```sh
sh scripts/package-macos.sh
open dist/Lark2Tapd.app
# 优化版本：sh scripts/package-macos.sh --release
```

`LARK2TAPD_MOCK` 接受 `1/true` 或 `0/false`；非法值、冲突的 `--mock --live` 或缺失参数会退出，而不是误启动真实模式。Finder 双击默认真实模式；要确保环境变量传给打包应用，可直接运行：

```sh
LARK2TAPD_MOCK=1 ./dist/Lark2Tapd.app/Contents/MacOS/lark2tapd
# 或通过 Launch Services 传命令行参数
open -n dist/Lark2Tapd.app --args --mock
```

只做本机 ad-hoc 签名，没有开发者证书签名、公证、安装到系统目录或远端发布。

## 操作流程

1. 打开或重新打开主界面会自动检查任务，顶部显示检查状态；「立即检查」和 `⌘R` 仍可手动触发。
2. 选择任务后，在同一详情页编辑标题、Markdown、目标项目空间、处理人和日期；内容实时渲染，可粘贴图片或通过「添加附件」选文件。
3. 可在标题左侧选择项目名前缀，提交时固定为 `【名称】标题`。配置中心按目标项目空间管理可选名称。
4. 直接点击「导入 TAPD」或「更新到 TAPD」。只有这个主动操作才写入远端；模拟来源变更最多显示一个「已更新」，旧缓存中的重复标记也会折叠。
5. 真实连接需以 `LARK2TAPD_MOCK=0` 或默认方式重新启动。两种模式的缓存、草稿和配置分别存储。

任务列表只显示标题、负责人和创建时间，不加字段名前缀，缺失项直接隐藏。完整的已解析飞书信息位于任务详情的可展开区域。文字使用中性色；马尔斯绿用于按钮填充、焦点和状态指示，不用于普通正文。

目标项目空间/处理人会先返回当前缓存，再异步查询最新数据；变化通过同一全局状态同步到各处，失败保留旧缓存，旧账户或旧编辑会话的迟到结果不会覆盖新内容。

菜单栏提供打开应用、未同步任务快捷入口、立即检查、暂停/开启定时检查和退出。`⌘R` 检查、`⌘1` 打开未同步列表、`⌘Q` 退出。关闭窗口后仍保留菜单栏与后台工作；退出应用后停止，不安装系统常驻服务。

## 真实连接

已按本机 `lark-cli 1.0.96` 与 `tapd-cli 1.8.1` 的命令契约实现。一键安装固定使用官方仍提供发布物的 TAPD CLI 1.15.0；原用户/任务命令依据已安装版本与官方源码核对。CLI 更新可能改变响应结构，升级后请重新验证。

- CLI 路径为**只读检测结果**。启动时检查已有路径、`PATH` 和应用私有安装目录；发现 CLI 后只显示测试按钮，没有安装按钮。未发现时显示安装入口。Finder 的环境可能不同，需要让工具处于可发现路径，或使用应用私有安装。
- TAPD API 地址仅允许官方 `https://api.tapd.cn`，防止令牌发送到任意地址。
- 填入飞书 App ID / App Secret、TAPD Token；需要已安装 CLI 和具备对应权限的应用。
- 在凭证表单点击「确认并保存到 Keychain」，再点击「连接飞书（OAuth）」。授权只请求 `task:task:read`，由 CLI 打开浏览器；用户需自行完成登录、MFA 和授权。
- TAPD 使用用户 Token；未实现未经文档确认的 TAPD OAuth。
- 分别点击「测试飞书 CLI 连接」和「测试 TAPD CLI 连接」。每项先检查可执行文件与版本，再验证账号及读取权限，结果分开显示；一项未配置不妨碍测试另一项，测试不会写入业务数据。
- 项目空间和处理人下拉框先使用 SQLite 缓存、后台刷新；切换目标项目空间会清空旧处理人，防止跨空间误用。只有有效项目/成员选择才能提交。
- 当前 CLI **只枚举管理员项目空间**。点击「添加目标项目空间」展开表单，填写 ID 和显示名称，先「检查权限」，再「确认添加」。任一字段改变后需重新检查；补充空间不会被管理员列表刷新删除。
- 飞书读取范围为 **创建人是本人，或负责人列表包含本人**，包含已完成项。仅关注的任务、其他人的任务和无法确定关系的任务不进入列表；提交前再次检查关系。两个平台的身份不能直接互换，不自动猜测处理人映射。

手工飞书用户 Token 可加密保存，但当前 CLI 不能可靠证明注入 Token 与已保存 OAuth 身份一致，因此真实同步对此模式失败关闭；请清除应用凭证并使用 OAuth，避免把另一账号的任务绑定到旧缓存。清除应用凭证不会登出外部 CLI。

空凭证输入表示保留已有值。更换 App ID 或从手工 Token 切回 OAuth 时，使用带二次确认的「清除凭证并重新连接」。密钥仅存于 macOS Keychain，不写入 SQLite、配置文件、命令行参数或日志；CLI 自身的授权缓存遵循其原生安全策略。

## 配置自动保存

不再有全局「保存配置」按钮。语言、主题、自动检查开关及合法间隔的编辑立即进入保存队列，按字段更新当前状态，不使用过期的整包配置覆盖其他修改。检查关闭时隐藏间隔输入；非法值保留原配置并在输入下提示原因。

默认目标项目空间/处理人、空间前缀、凭证等相互关联的字段放入确认表单，只有确认后一起提交。凭证保存成功才清空输入。CLI 测试按钮不因其他后台读取而禁用，重复读取会合并；写入仍串行处理。

## Markdown、图片和附件

- 内容实时使用原生 Markdown 组件渲染，没有 WebView。图片剪贴板和 Finder 复制文件都支持；不把本机文件路径粘成将被提交的文本。
- 每任务最多 10 个附件，单个本地文件最多 20 MiB。粘贴图转换为 PNG 后需小于 5 MB；预览解码限制单边 8192、总像素约 1600 万和内存预算。SVG 等无法安全解码的粘贴格式明确报错。
- 文件复制到按账户隔离的私有缓存，使用内容哈希验证；正文保存 `attachment:<id>`，不发送 `file://` 或本机路径。渲染器只读取当前任务获准的缓存图片，阻止外部图片及 data URL 自动加载。
- 已选择/粘贴但还在读取的文件会占用容量，并阻止提交，避免提交时遗漏。失败只清理该次操作的占位；切换任务、重新读取、移除图片后，迟到结果不会串入新的草稿。
- 提交先持久化任务映射，再逐个记录上传意图和回执。普通文件关联到已有 TAPD 条目；图片成功后回填正文。正文回填有独立持久化标记，附件或回填未完成会出现在「待处理」，不误报为全部已同步。
- 已上传附件在 TAPD 管理，不从本地草稿静默删除远端文件。上传结果不确定时停止自动重试，需人工核对；当前不提供针对未知上传结果的自动恢复。
- 普通附件上传有官方 CLI 与腾讯部署 API 文档支持，但 `api.tapd.cn` 实际权限/部署行为尚未实写验收；不支持时会明确失败。飞书原任务的附件元数据不等于已下载文件，不会自动搬运未取得的源文件。

## 缺失 CLI 的应用内安装

真实模式下，配置中心提供各 CLI 安装入口；必须先核对来源、版本、目录和要求，再点击「确认安装」。取消不会下载或修改工具。安装使用应用数据目录下的 `tools/`，不使用 `sudo`、不修改 shell 配置，也不覆盖已有全局 CLI；验证成功才保存新路径。版本目录已存在时不盲目覆盖，重启时会检测其中已安装的工具。

- **飞书 CLI 1.0.96**：官方 `@larksuite/cli` npm 包。需要 Node.js ≥20、npm、curl 和 tar；缺少 Node/npm 时给出明确错误，请先从 [Node.js 官方网站](https://nodejs.org/en/download) 安装。npm 依赖生命周期默认禁用，只显式调用已核实的官方安装入口；官方二进制安装器使用包内 SHA-256 校验。
- **TAPD CLI 1.15.0**：从 `cnb.cool/tapd.cn/skills/tapd-cli` 官方固定版本发布地址直接 HTTPS 下载，校验本机架构、版本及 CLI 标识。不运行会修改 shell 配置的 `install.sh`。官方未提供加密校验值/签名，因此架构和版本检测**不等于密码学真实性验证**。
- 安装过程不注入业务凭证；发生错误保留原配置，并只清理本次创建的安装目录。测试使用替身进程，不会真的安装软件。

## 数据与冲突规则

- 默认数据目录：`~/Library/Application Support/Lark2Tapd`，目录权限 `0700`。
- Toasty 类型模型中保存原子 JSON 快照，包含设置、任务缓存、草稿、来源基线、目标资源类型/ID 及写入日志。适用于个人任务量；不引入服务器或后台守护进程。
- 单目录只有一个进程可写，防止多个桌面实例覆盖状态。
- mock 与 live 独立；live 按已验证的平台账户隔离。凭证更换不应丢失同账户映射。
- 项目与每个项目的成员缓存按已验证账户隔离，刷新失败不会覆盖旧缓存；提交前重新验证缓存中的项目和处理人是否仍有效。旧版本没有来源范围证明的任务先隐藏，重新刷新后按新规则展示；离开本人范围的记录只隐藏，不删除同步关联或不确定日志。
- 已同步任务不会重复创建。来源变化仅进入待处理，不会自动覆盖目标。
- 草稿绑定来源版本、账户及编辑会话。来源刷新或账户切换会使旧提交失效。TAPD 被他人修改时先阻止覆盖，可在详情中「核对 TAPD 最新内容」并明确接受该版本，再继续编辑和更新；这不是正常导入的必经预览页。
- 写入前持久化「待核对」日志。超时、崩溃或写后读回失败不会盲目重试。先在 TAPD 查找 `[lark-task:GUID]`，再填写已有条目 ID 验证关联；恢复后仍需确认更新。
- 新任务可能在 TAPD 中实际是 `Story` 资源；记录真实资源类型并选择对应读写命令，不使用错误的旧任务更新接口。
- 映射带可选前缀的标题、Markdown 描述、指定处理人、日期及显式添加的附件。飞书完成状态可见，但不会猜测不同 TAPD 项目的状态流。
- 描述确定性渲染为安全 HTML，附加飞书来源链接及稳定标记；禁用危险 HTML/协议。CLI 和服务端仍可能规范化 HTML，无法确认等价的回读保持待核对状态。
- 远端先读再写不是服务器原子 compare-and-swap，最后一次检查和写入间仍存在小窗口；TAPD 未验证条件更新能力。

## 验证

```sh
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
sh scripts/package-macos.sh
```

覆盖层次：

- 核心：真实 SQLite 重启、原子日志、去重、草稿过期、并发目标变更、不确定写入恢复与 mock 全流程。
- CLI：临时假可执行文件验证参数、分页、业务错误、环境隔离、超时和输出边界，不写真实业务数据。
- 桌面 E2E：GPUI headless 的真实点击/键盘输入经过工作线程、核心引擎和 SQLite，覆盖直接导入/更新、标题前缀、自动保存、项目空间检查表单、标准选择器/日期、图片剪贴板/Finder 文件粘贴、附件取消与迟到结果隔离。
- 安装与诊断：固定来源/版本、私有目录、取消无副作用、错误回滚、版本识别、逐平台账号读取检查；真实安装不作为测试副作用。

**证据边界：** headless GUI E2E 不等于 macOS 系统级自动化。真实 Keychain 读写、浏览器 OAuth、真实 TAPD 写入、系统通知权限和通知展示必须在用户授权环境另行验收；不会把 mock 成功声称为真实联调成功。菜单栏与原生窗口仍需打包应用烟测。系统通知需要应用身份以及系统通知设置允许；从 `cargo run` 启动时不能保证通知展示。

## macOS 控制台日志

`TSM AdjustCapsLockLEDForKeyTransitionHandling`、`IMKCFRunLoopWakeUpReliable` 涉及 macOS 键盘/输入法服务，仅凭这两行不能判断 Rust 应用崩溃。本项目未通过屏蔽系统日志来处理它们。若窗口退出或输入异常，应同时收集退出码、Rust panic/backtrace 和具体操作。

`block v0.1.6` 的 future-incompatibility 是上游依赖对未来 Rust 的警告；当前工具链构建通过，但警告仍保留。

## 代码结构

- `crates/core`：领域状态、同步规则、Toasty 持久化、演示网关。
- `crates/bridge`：真实 CLI 契约、安全子进程、Keychain 和身份隔离。
- `crates/desktop`：GPUI 界面、串行工作队列、菜单栏和系统通知。
- `scripts/package-macos.sh`：本地 `.app` 打包和临时签名。

任务内容不是密钥，但包含业务信息：当前 TAPD CLI 仅支持 `key=value` 参数，标题/描述可能被同机进程参数检查读取。数据库只保护访问权限，不加密全部任务内容；设备磁盘加密可提供额外保护。
