# Lark → TAPD

仅面向 macOS 的飞书任务同步桌面应用。Rust + GPUI Kit，马尔斯绿主题，中英文、亮色/暗色/跟随系统，SQLite 持久化与设备 Keychain 凭证存储。

**飞书是来源，写入由你确认。** 后台检查不会自动覆盖 TAPD；编辑后直接点击「导入 TAPD / 更新到 TAPD」写入，不再经过预览页。应用只支持真实连接，不提供演示模式或模拟任务入口。测试替身仅用于隔离的自动化测试。

## 本地运行

需要 macOS、Rust 2024 工具链、Xcode 与命令行开发工具。项目锁定 GPUI Kit 0.7.1，使用 Toasty 0.11；请提交并保留 `Cargo.lock`。

```sh
# 正常启动（先移除旧版本的 LARK2TAPD_MOCK 环境变量）
unset LARK2TAPD_MOCK
cargo run --locked -p lark2tapd
# 使用独立的数据目录（仍为真实连接，不是演示环境）
cargo run --locked -p lark2tapd -- --data-dir ./target/local-data
```

构建可双击启动的桌面应用：

```sh
sh scripts/package-macos.sh
open dist/Lark2Tapd.app
# 优化版本：sh scripts/package-macos.sh --release
```

`--mock` 和任何非空的 `LARK2TAPD_MOCK`（包括 `0`、`false`）都会明确提示演示模式已移除并退出，不会静默进入真实账户。冗余的 `--live` 也不再接受；启动参数仅保留 `--data-dir PATH` 与 `--help`。Finder 双击同样只支持真实连接。

只做本机 ad-hoc 签名，没有开发者证书签名、公证、安装到系统目录或远端发布。

## 操作流程

1. 打开或重新打开主界面会自动检查任务，顶部显示检查状态；「立即检查」和 `⌘R` 仍可手动触发。
2. 在左侧「未同步 / 待处理 / 已同步」三段式列表选择任务，右侧编辑标题、Markdown、目标项目空间、处理人和日期。Markdown 在同一区域编辑和渲染，光标附近显示语法标记，不再另设下方预览；可粘贴图片或通过「添加附件」选文件。
3. 标题输入组左侧可选择前缀。配置中心按目标项目空间逐项添加、删除前缀，只有点击「添加」才展开输入。前缀按输入原样使用：例如 `【产品】`、`BUG: ` 均不会自动包装或去掉空格。旧配置在首次读取时一次性迁移为带 `【】` 的原有表现，不改变既有同步标题。
4. 直接点击「导入 TAPD」或「更新到 TAPD」。只有这个主动操作才写入远端；来源变更最多显示一个「已更新」，旧缓存中的重复标记也会折叠。
5. 首次使用先在设置中确认 CLI 可用，再配置账号并检查权限；历史演示缓存不会被真实连接读取。

主界面为任务列表与详情两栏。列表卡片的标题左对齐，下方显示描述摘要；处理人和创建时间放在底部同一排，缺失项不显示。卡片不使用选中描边，悬浮为浅色填充，按下和选中为更深填充，保留键盘焦点提示。飞书图标位于任务详情标题行最右侧，悬停显示说明；已同步状态采用实心圆勾，附件尚未完成时仍显示待处理。文字使用中性色，品牌色用于操作与状态强调。

任务草稿仍需显式保存。重复点击当前任务不会重新加载；切换任务、关闭主窗口或从菜单/快捷键/托盘退出时，若有未保存修改或未完成媒体操作，会要求取消或明确丢弃。取消后可使用已有「保存草稿」按钮。账号或任务范围失效会结束旧确认会话，旧确认不能操作新账号或已离开范围的任务。系统强杀、崩溃或断电不提供未保存输入恢复保证。

主窗口不再保留固定底部状态栏。操作成功使用短暂提示，错误需要手动关闭；后台错误在应用未激活或窗口关闭期间也会保留，重新打开窗口可查看。无关的配置保存成功不会覆盖未确认的错误。

目标项目空间/处理人会先返回当前缓存，再异步查询最新数据；变化通过同一全局状态同步到各处，失败保留旧缓存，旧账户或旧编辑会话的迟到结果不会覆盖新内容。

设置可从顶栏齿轮、macOS 的 L2T 菜单或应用菜单打开，也支持 `⌘,`。设置是独立的非模态原生窗口，重复打开只置前；与主窗口共享偏好，关闭设置不会切换或清空任务草稿。主窗口关闭后仍可从菜单栏单独打开设置。

菜单栏还提供打开应用、未同步任务快捷入口、立即检查、暂停/开启定时检查和退出。`⌘R` 检查、`⌘1` 打开未同步列表、`⌘W` 关闭当前窗口、`⌘Q` 退出。关闭窗口后仍保留菜单栏与后台工作；正常退出时关闭业务队列、取消并等待后台 CLI 回收，原生任务结束后才释放数据目录锁，不安装系统常驻服务。GPUI 退出 hook 的等待有平台时限，因此另有正常进程退出屏障；同步写入/安装可能要等现有有界调用结束，不承诺立即退出。强杀或 abort 不保证执行退出屏障。

## 真实连接

已按本机 `lark-cli 1.0.96` 与 `tapd-cli 1.8.1` 的命令契约实现。一键安装固定使用官方仍提供发布物的 TAPD CLI 1.15.0；原用户/任务命令依据已安装版本与官方源码核对。CLI 更新可能改变响应结构，升级后请重新验证。实际账号读取、提交及恢复入口与诊断共用版本门禁，不支持的版本会在访问凭据或业务命令前拒绝；不再允许“检测失败但仍继续写入”。独立连接测试仍只检查选中的服务。

- 配置按飞书与 TAPD 分区，帮助图标位于相关字段标签旁。CLI 路径为**不可交互的淡色检测结果**。启动和点击「检测 CLI」都会重新发现路径：优先保留有效的已配置绝对路径，其次检查应用私有版本目录内的 `lark-cli` / `tapd-cli` 文件，再查 `PATH`、`/opt/homebrew/bin` 和 `/usr/local/bin`。找到的路径提交到全局偏好并同步当前账号的运行时视图，重启不再只依赖当时的 `PATH`；已打开的设置窗口同步显示新路径。仅发现文件不代表版本受支持，版本及可执行身份探测通过后才开放账号配置。未找到时保留原配置并明确提示缺少可执行文件，不自动安装、卸载或重新授权。路径改变会使该服务的旧验证记录失效并取消旧读取结果；授权进行中不切换 CLI 路径。
- 界面不展示 TAPD API 地址；仍通过 CLI 调用，只允许官方 `https://api.tapd.cn`，防止令牌发送到任意地址。
- 设置按「账号连接」「导入设置」「后台检查」「外观与语言」分类。点击「连接飞书」或「连接 TAPD」才展开该服务的表单；需要已安装 CLI 和具备对应权限的应用。
- 在各自表单点击「保存并连接」，自动保存该服务到 Keychain，再执行授权或连接检查；不是输入时逐字保存。飞书设备授权返回链接后，由用户点击打开浏览器，自行完成登录、MFA 和授权；应用不会自动打开浏览器。授权等待在后台进行，不阻塞偏好保存或清除/重连，旧授权的迟到结果不会覆盖新状态。保存和验证状态分开显示，连接失败不等于保存失败。
- 飞书授权必须使用匹配 App ID 的原生 CLI profile，不能仅向授权命令注入环境变量。只有显式「保存并连接」才允许通过官方 `profile add` 创建应用专用 profile，Secret 经 stdin 进入 CLI 原生密钥存储，不写入明文配置或命令行参数；保留已有 profile 和当前激活选择，匹配 App ID 的已有 profile 会复用而不自动轮换 Secret。配置损坏、名称冲突或版本不兼容会停止并显示安全诊断，启动、本地探测和「检查连接」不会创建 profile。
- TAPD 使用用户 Token；未实现未经文档确认的 TAPD OAuth。
- 「测试连接」在编辑表单中紧邻「保存并连接」，保存后紧邻「编辑配置」。测试结果显示在各服务独立、可复用的原生窗口中，包含测试时间、权限明细和失败原因；`⌘W` 或 `Esc` 关闭结果窗口，不影响主窗口和设置。本地 CLI 探测不由应用主动加载账户凭证，CLI 自身可能读取原生配置或版本缓存；账号检查另行验证身份及读取权限，结果分开显示，写入权限未经业务写入验证时明确显示未知；一项未配置不妨碍测试另一项，测试不会写入业务数据。
- 项目空间和处理人下拉框先使用 SQLite 缓存、后台刷新；切换目标项目空间会清空旧处理人，防止跨空间误用。只有有效项目/成员选择才能提交。
- 当前 CLI **只枚举管理员项目空间**。点击「添加目标项目空间」展开表单，填写 ID 和显示名称，先「检查权限」，再「确认添加」。任一字段改变后需重新检查；补充空间不会被管理员列表刷新删除。
- 飞书读取范围为 **未完成，且创建人是本人或负责人列表包含本人**。每页通过 `--include-complete=false` 在服务端过滤已完成历史任务；详情读回时再次排除期间已完成的任务，逾期但未完成的任务仍保留。仅关注的任务、其他人的任务和无法确定关系的任务不进入列表；提交前再次检查关系。完整刷新成功后，不再返回的旧任务退出当前列表，但保留草稿、TAPD 映射和不确定记录，不自动完成或删除 TAPD 条目。两个平台的身份不能直接互换，不自动猜测处理人映射。

手工飞书用户 Token 可加密保存，但当前 CLI 不能可靠证明注入 Token 与已保存 OAuth 身份一致，因此真实同步对此模式失败关闭；请清除应用凭证并使用 OAuth，避免把另一账号的任务绑定到旧缓存。清除应用凭证不会登出外部 CLI。

空凭证输入表示保留已有值；修改飞书应用时 App ID 与 Secret 必须成对提交。更换 App ID 或从手工 Token 切回 OAuth 时，使用该服务下带二次确认的「清除凭证并重新连接」。仅有已保存信息时显示清除入口，清除飞书不会影响 TAPD，反之亦然。密钥仅存于 macOS Keychain，不写入 SQLite、配置文件、命令行参数或日志；CLI 自身的授权缓存遵循其原生安全策略。

连接验证成功后，保存配置的最近通过时间会持久化；重新检测 CLI 或连接失败不会删除此前的成功时间。历史时间不代表当前令牌仍有效，不作为写入授权。凭证、CLI 路径或 TAPD 项目空间变化后，旧记录失效；飞书重新授权也会失效旧记录，避免沿用另一用户的验证。每次「保存并连接」都重新验证，不复用此前结果，但验证在后台静默进行，不自动打开或置前结果窗口。只有主动点击「测试连接」才打开结果窗口；需要 OAuth 时仍在设置页显示授权入口。

表单测试使用当次输入的内存快照，未保存的 TAPD Token 不会写入 Keychain，也不会更新已保存配置的通过时间。飞书新 App ID／Secret 不能借旧原生 profile 测试，需先「保存并连接」完成配置与授权。

主界面未配置提示提供「配置飞书」「配置 TAPD」文字链接；服务相关错误提示也提供设置入口。链接会复用设置窗口并定位对应小节：CLI 未就绪时定位检测区域，就绪时展开连接表单。

## 配置自动保存

不再有全局「保存配置」按钮。语言、主题、自动检查开关及合法间隔的编辑立即进入保存队列，按字段更新当前状态，不使用过期的整包配置覆盖其他修改。检查关闭时隐藏间隔输入；非法值保留原配置并在输入下提示原因。

默认目标项目空间和处理人选择后自动保存，不再需要确认默认目标；切换空间与清空旧处理人原子保存。初始化控件、更新下拉选项不会误触发保存。空间前缀仍逐项确认添加；保存回执只在项目和输入仍对应本次提交时结束表单，迟到快照或删除回执不清空新输入。未配置 TAPD 时显示连接引导。刷新按钮分别位于输入框后，添加项目空间使用标题右侧带 tooltip 的加号按钮。

对应控件或编辑区域下方显示「保存中…」或绿色勾选「已保存」。保存提示仅属于当前设置窗口会话：加载已有配置不会显示「已保存」，未改变偏好值的重复选择也不会生成保存成功标记。关闭设置窗口清除提示与待确认序号，但不撤销实际保存；重新打开不会继承旧提示，旧窗口的延迟回执也不会点亮新窗口。继续编辑会清除旧保存标记；回执按请求序号匹配，旧请求不能将新输入标为已保存。失败使用同位置的轻量折叠项，收起显示分类与标题，展开查看脱敏详情；凭证已保存不等于连接已验证。

各服务的凭证保存成功后，只清空并收起该服务表单；保存失败保留输入，取消表单会清空其未保存输入。CLI 检查按钮不因其他后台读取而禁用，重复读取会合并；写入仍串行处理。

帮助图标支持悬停、点击或键盘打开，浮层内有主题色外链按钮；移动到浮层内不会消失，`Esc` 或点击外部关闭。`Tab` / `Shift+Tab` 遍历设置控件并滚动露出焦点，`Enter` / 空格激活按钮；`Esc` 优先关闭帮助、下拉或清除确认，不丢弃正在填写的连接表单。

## 控制台日志与输入法诊断

日志仅写终端 stderr，暂不记录文件。格式为本地时间、级别、模块和事件：`settings.language`、`settings.theme`、`settings.destination`、`settings.polling`、`settings.prefixes`、`connection.lark`、`connection.tapd`、`tasks.lark` 等。设置提交及保存结果分别记录；失败记录分类，并在可用时附带经过校验的 `exit_code` 与整数 `api_code`，具体脱敏详情在界面查看。CLI/API 失败优先按明确的错误类型分类，恢复建议中的认证、权限等词不会改变分类；普通 `api` 或 `unknown` 不代表令牌失效。不打印 Secret、Token、授权码、原始 CLI 输出、任务标题或正文。

每轮任务完整读取且成功更新缓存后，打印一行 `read / unfinished / added / changed / unimported / attention / unsynced` 数量。新增和变化对比上一份缓存；只统计当前范围内任务。`unsynced` 包含未导入、待更新、待核对和附件/正文未完成的任务，不把这些状态当成全部已同步。

刷新额外输出 `[tasks.refresh]` 分阶段日志，每轮有独立 `id` 和触发来源 `startup / reopen / manual / polling`。阶段包括 `credential_load`、`lark_identity`、`tapd_identity`、`lark_list_page`、`lark_task_details`；提供页号、详情进度、耗时和剩余预算，不输出任务 GUID 或分页令牌。`completed / scheduled` 是本轮已完成与截至当前页已安排的详情请求数，不等同于最终保留的任务数。

- `event=request_timeout`：某个 CLI 调用超过单次时间限制，优先检查该阶段的网络、代理或 CLI。
- `event=refresh_budget_timeout`：整轮 120 秒预算耗尽，或剩余预算不足以容纳服务端要求的冷却；可以看到当时已经完成多少详情。
- `event=cancelled`：配置或账号切换等操作取消了旧读取。
- `event=request_failed`：其他请求失败；结合随后 `operation_failed` 的分类、`exit_code` 和 `api_code` 定位。`detail` 是当前页内的详情请求序号，不是任务 ID。
- `event=rate_limit_wait`：命中飞书 `99991400` 限流，当前轮暂停新请求；`retry` 为该请求的重试序号，`wait_ms` 为本次冷却时长，不是整轮累计耗时。
- `event=rate_limited` / `category=rate_limit`：有限重试后仍被限流，保留旧缓存；不要因此重新授权。

详情读取最多四路并发，分页仍顺序读取；刷新中的分页和详情请求跨页共享启动节流，间隔至少 125ms（约 8 次/秒），避免仅控制并发仍触发[详情接口 10 次/秒限制](https://open.feishu.cn/document/task-v2/task/get)。仅对明确的 `99991400` 重试当前失败的只读请求：CLI 提供有效 `retry_after_seconds` 时遵守服务端冷却，否则按 1、2、4 秒退避，最多重试三次；冷却期间全轮暂停启动新请求，已成功的详情不重读。等待仍计入 120 秒预算且支持取消。1000 条是安全上限而非吞吐承诺：若 1000 条都要详情，单是 125ms 的发起间隔已超过 120 秒预算；达到该规模需单独设计增量或可恢复扫描，不能用部分结果替换缓存。其他错误不自动重试，TAPD 写入和上传行为不变。任一详情最终失败都会保留旧缓存，不会把半份列表写入数据库。标准代理环境变量及大小写形式会原样传给 CLI，但不记录值。`proxy_env_set` 仅表明进程环境里存在代理相关变量，不证明请求实际经过代理；Finder 启动不一定继承终端环境，应用不替你设置代理。

`app.lifecycle` 记录启动、退出请求、退出通知和事件循环返回；`ui.window` 记录窗口关闭。Rust panic 记录代码位置但不输出可能含敏感数据的 payload；需要堆栈时可用 `RUST_BACKTRACE=1`。

`IMKCFRunLoopWakeUpReliable` 来自 macOS 输入法通信层，单独这一行不能证明应用崩溃。其他 GUI 及[原生 AppKit 最小复现](https://github.com/Richy-Z/BUG-IMKCFRunLoopWakeUpReliable)也有同名报告；[Electron 维护者的结论](https://github.com/electron/electron/issues/45002)只适用于其场景，不能直接当作本应用已修复。不要通过禁用输入法或关闭系统日志掩盖它。若伴随输入异常或意外退出，请记录复现操作及退出码：

```sh
RUST_BACKTRACE=1 cargo run --locked -p lark2tapd
printf 'exit_code=%s\n' "$?"
```

## Markdown、图片和附件

- 内容使用 `zorite-editor 0.11.1` 的原生 GPUI 同区编辑器，没有 WebView。保留上游 MIT 许可及可审查的本地补丁，修复中文组合选区、组合撤销、加载时修改正文和媒体粘贴入口。正文加载不自动规范化数学围栏。图片剪贴板和 Finder 复制文件都支持；不把本机文件路径粘成将被提交的文本。
- 图片读取完成时只替换对应占位符，保留选区及撤销历史；组合输入期间延迟回填，撤销不会恢复已失效的 pending 引用。提交中、来源过期或写入结果不确定时，同一区域切换为只读渲染并撤销编辑焦点。
- 每任务最多 10 个附件，单个本地文件最多 20 MiB。粘贴图转换为 PNG 后需小于 5 MB；预览解码限制单边 8192、总像素约 1600 万和内存预算。SVG 等无法安全解码的粘贴格式明确报错。
- 文件复制到按账户隔离的私有缓存，使用内容哈希验证；正文保存 `attachment:<id>`，不发送 `file://` 或本机路径。渲染器只读取当前任务获准的缓存图片，阻止外部图片及 data URL 自动加载。
- 已选择/粘贴但还在读取的文件会占用容量，并阻止提交，避免提交时遗漏。失败只清理该次操作的占位；切换任务、重新读取、移除图片后，迟到结果不会串入新的草稿。
- 提交先持久化任务映射，再逐个记录上传意图和回执。普通文件关联到已有 TAPD 条目；图片成功后回填正文。正文回填有独立持久化标记，附件或回填未完成会出现在「待处理」，不误报为全部已同步。
- 已上传附件在 TAPD 管理，不从本地草稿静默删除远端文件。上传结果不确定时停止自动重试，需人工核对；当前不提供针对未知上传结果的自动恢复，也没有应用内人工认领回执入口；此状态会阻止该任务后续提交，需要单独设计安全恢复流程，不能清标记后盲目重传。
- 普通附件上传有官方 CLI 与腾讯部署 API 文档支持，但 `api.tapd.cn` 实际权限/部署行为尚未实写验收；不支持时会明确失败。飞书原任务的附件元数据不等于已下载文件，不会自动搬运未取得的源文件。

## 缺失 CLI 的应用内安装

真实模式下，配置中心提供各 CLI 安装入口；必须先核对来源、版本、目录和要求，再点击「确认安装」。取消不会下载或修改工具。安装使用应用数据目录下的 `tools/`，不使用 `sudo`、不修改 shell 配置，也不覆盖已有全局 CLI；验证成功才保存新路径。版本目录已存在时不盲目覆盖，重启时会检测其中已安装的工具。安装失败保留已展示的确认计划，允许用户再次明确确认，不自动重试。

- **飞书 CLI 1.0.96**：官方 `@larksuite/cli` npm 包。需要 Node.js ≥20、npm、curl 和 tar；缺少 Node/npm 时给出明确错误，请先从 [Node.js 官方网站](https://nodejs.org/en/download) 安装。npm 依赖生命周期默认禁用，只显式调用已核实的官方安装入口；官方二进制安装器使用包内 SHA-256 校验。
- **TAPD CLI 1.15.0**：从 `cnb.cool/tapd.cn/skills/tapd-cli` 官方固定版本发布地址直接 HTTPS 下载，校验本机架构、版本及 CLI 标识。不运行会修改 shell 配置的 `install.sh`。官方未提供加密校验值/签名，因此架构和版本检测**不等于密码学真实性验证**。
- 安装过程不注入业务凭证；发生错误保留原配置，并只清理本次创建的安装目录。测试使用替身进程，不会真的安装软件。

## 数据与冲突规则

- 默认数据目录：`~/Library/Application Support/Lark2Tapd`，目录权限 `0700`。
- Toasty 类型模型中保存原子 JSON 快照，包含设置、任务缓存、草稿、来源基线、目标资源类型/ID 及写入日志。适用于个人任务量；不引入服务器或后台守护进程。
- 全局 `preferences-live.db` 是配置的唯一提交点；账号快照中的配置是运行时副本，启动和账号切换时从全局配置恢复。普通配置只有全局保存成功后才更新 UI/内存，账号库副本写入失败不再造成“保存失败但重启生效”。任务、草稿及写入日志仍必须先落盘再推进内存。凭据写入是独立的外部副作用：一旦成功就立即作废旧身份，即使后续偏好保存失败也不能接受旧代结果。
- 单目录只有一个进程可写，防止多个桌面实例覆盖状态。
- 真实连接按已验证的平台账户隔离，不再访问历史演示数据库。凭证更换不应丢失同账户映射。
- 项目与每个项目的成员缓存按已验证账户隔离，刷新失败不会覆盖旧缓存；提交前重新验证缓存中的项目和处理人是否仍有效。旧版本没有来源范围证明的任务先隐藏，重新刷新后按新规则展示；离开本人范围的记录只隐藏，不删除同步关联或不确定日志。
- 已同步任务不会重复创建。来源变化仅进入待处理，不会自动覆盖目标。
- 草稿绑定来源版本、账户及编辑会话。来源刷新或账户切换会使旧提交失效。TAPD 被他人修改时先阻止覆盖，可在详情中「核对 TAPD 最新内容」并明确接受该版本，再继续编辑和更新；这不是正常导入的必经预览页。
- 写入前持久化「待核对」日志。超时、崩溃或写后读回失败不会盲目重试。先在 TAPD 查找 `[lark-task:GUID]`，再填写已有条目 ID 验证关联；恢复后仍需确认更新。
- 新任务可能在 TAPD 中实际是 `Story` 资源；记录真实资源类型并选择对应读写命令，不使用错误的旧任务更新接口。
- 映射带可选前缀的标题、Markdown 描述、指定处理人、日期及显式添加的附件。飞书完成状态可见，但不会猜测不同 TAPD 项目的状态流。
- 描述确定性渲染为安全 HTML，附加飞书来源链接及稳定标记；禁用危险 HTML/协议。CLI 和服务端仍可能规范化 HTML，无法确认等价的回读保持待核对状态。
- 远端先读再写不是服务器原子 compare-and-swap，最后一次检查和写入间仍存在小窗口；TAPD 未验证条件更新能力。

## 验证

```sh
cargo fmt --all -- --check
cargo test --workspace --locked
cargo test --locked --manifest-path vendor/zorite-editor/Cargo.toml --lib --target-dir target
cargo clippy --workspace --all-targets --locked -- -D warnings
sh scripts/package-macos.sh
```

覆盖层次：

- 核心：真实 SQLite 重启、原子日志、去重、草稿过期、并发目标变更、不确定写入恢复与 mock 全流程。
- CLI：临时假可执行文件验证参数、分页、业务错误、环境隔离、超时和输出边界，不写真实业务数据。
- 桌面 E2E：GPUI headless 的真实点击/键盘输入经过工作线程、核心引擎和 SQLite，覆盖直接导入/更新、标题前缀、自动保存、项目空间检查表单、标准选择器/日期、图片剪贴板/Finder 文件粘贴、附件取消与迟到结果隔离。
- 安装与诊断：固定来源/版本、私有目录、取消无副作用、错误回滚、版本识别、逐平台账号读取检查；真实安装不作为测试副作用。

**证据边界：** headless GUI E2E 不等于 macOS 系统级自动化。真实 Keychain 读写、浏览器 OAuth、真实 TAPD 写入、系统通知权限和通知展示必须在用户授权环境另行验收；不会把 mock 成功声称为真实联调成功。菜单栏与原生窗口仍需打包应用烟测。系统通知需要应用身份以及系统通知设置允许；从 `cargo run` 启动时不能保证通知展示。

## macOS 控制台日志

`TSM AdjustCapsLockLEDForKeyTransitionHandling`、`IMKCFRunLoopWakeUpReliable` 涉及 macOS 键盘/输入法服务，仅凭这两行不能判断 Rust 应用崩溃。本项目未通过屏蔽系统日志来处理它们。若窗口退出或输入异常，应同时收集退出码、Rust panic/backtrace 和具体操作。

`block v0.1.6` 的 future-incompatibility 是上游依赖对未来 Rust 的警告；当前工具链构建通过，但警告仍保留。

## 代码结构

- `crates/core`：领域状态、同步规则、Toasty 持久化、演示网关。
- `crates/bridge`：真实 CLI 契约、安全子进程、Keychain 和身份隔离。
- `crates/desktop`：GPUI 界面、串行工作队列、菜单栏和系统通知。
- `vendor/zorite-editor`：固定发布版的 MIT 编辑核心与必要补丁、补丁回归测试；不包含 GPL Zorite 应用。
- `scripts/package-macos.sh`：本地 `.app` 打包和临时签名。

任务内容不是密钥，但包含业务信息：当前 TAPD CLI 仅支持 `key=value` 参数，标题/描述可能被同机进程参数检查读取。数据库只保护访问权限，不加密全部任务内容；设备磁盘加密可提供额外保护。
